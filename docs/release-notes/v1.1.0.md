## SSH Workspaces

You can now connect an SSH host directly as a kmux workspace. Split
terminals, run several agent sessions side by side, and pick up where you
left off after reopening the app.

![SSH Connections settings](./assets/v1.1.0/ssh-workspaces.png)

### Getting started

1. Create a workspace in the left sidebar, then switch it over with
   **Convert to SSH Workspace...** from the Command Palette or the workspace
   menu.
2. Manage connections under **Settings → SSH Connections**, or import an
   existing OpenSSH alias with **Sync SSH config**.

## Markdown Preview

Reading a document an agent just wrote no longer means leaving kmux for an
external editor. Click a Markdown file path in the terminal and it opens in a
preview beside your session.

![Markdown preview beside a terminal session](./assets/v1.1.0/markdown-preview.png)

### Getting started

1. Find a path to an existing Markdown file in the terminal output.
2. **Command-click** it on macOS, or **Control-click** it on Linux.
3. Read the document in the preview on the right while you keep working in the
   terminal.

## Agent Launcher Commands

kmux can now use a command of your choosing when it resumes an agent
conversation from session history. If your environment wraps the official CLI
or runs it through a separate profile command, existing sessions keep working —
you no longer have to fall back to the official CLI to continue them.

Claude, Codex, and Antigravity each take one active profile per environment.
Local profiles are never inherited by SSH.

### Getting started

1. Choose **Settings → Open settings.json**.
2. Put local profiles directly under `agents`.
3. Save the file and restart kmux.

```json
{
  "agents": {
    "claude": {
      "command": "ccs",
      "args": ["enterprise", "--"],
      "sessionRoot": "~/.ccs/shared/context-groups/default/projects"
    },
    "codex": {
      "command": "ccsxp",
      "args": []
    }
  }
}
```

### Profile fields

- **`command`** — the executable that launches the agent. It must be on the
  `PATH` of the host where the session runs; if kmux cannot find it, resuming
  that session is disabled rather than quietly reverting to the official CLI.
  Omit it to use the vendor's native CLI.
- **`args`** — fixed arguments inserted after `command` and before the
  session-resume arguments kmux generates. The Claude profile above runs as
  `ccs enterprise -- --resume <id>`.
- **`sessionRoot`** — where kmux reads sessions from, both for history and for
  token and cost usage. Must be an absolute path or start with `~/`. If the
  directory is missing or unreadable, kmux reports no sessions for that
  profile. Omit it to use the vendor's native session store.

### SSH profiles

SSH settings are optional. To use a different profile on SSH hosts, add only
the vendors you need under `agents.ssh`:

```json
{
  "agents": {
    "ssh": {
      "claude": {
        "command": "claude-remote",
        "args": [],
        "sessionRoot": "~/.claude/projects"
      }
    }
  }
}
```
