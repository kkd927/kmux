## SSH Workspaces

이제 SSH 호스트를 kmux의 워크스페이스로 직접 연결할 수 있습니다. 원격
프로젝트에서도 로컬과 동일하게 터미널을 나누고, 여러 에이전트 세션을
나란히 실행하고, 앱을 다시 열어 작업을 이어갈 수 있습니다.


### 시작하기

1. **Settings → SSH Connections**에서 새 연결을 추가하거나
   **Sync SSH config**로 기존 OpenSSH 별칭을 가져옵니다.
2. Command Palette 또는 워크스페이스 메뉴에서
   **Convert to SSH Workspace...**를 선택합니다.
3. 연결할 호스트를 고른 뒤 현재 워크스페이스를 전환할지, 새
   워크스페이스를 만들지 선택합니다.

## Markdown Preview

에이전트가 작성한 문서를 확인하기 위해 터미널과 외부 편집기를 오갈 필요가
없어졌습니다. 터미널에 출력된 Markdown 파일 경로를 클릭하면 kmux 안에서
미리보기가 열립니다.

### 시작하기

1. 터미널에서 실제 Markdown 파일 경로를 찾습니다.
2. macOS에서는 **Command-click**, Linux에서는 **Control-click**합니다.
3. 오른쪽에 열린 미리보기에서 문서를 확인하고, 터미널 작업을 그대로
   이어갑니다.

## Agent Launcher Commands

세션 히스토리에서 에이전트 대화를 재개할 때 kmux가 사용할 명령어와 고정
인자를 설정할 수 있습니다. 공식 CLI 대신 사내 래퍼나 별도의 프로필 명령을
사용하는 환경에서도 기존 세션을 바로 이어갈 수 있습니다.

설정은 로컬과 SSH 환경을 분리해서 적용할 수 있으며 Claude, Codex,
Antigravity를 지원합니다.

### 설정하기

1. **Settings → Open settings.json**을 선택합니다.
2. `agents.local` 또는 `agents.ssh` 아래에 에이전트별 `command`와 `args`를
   추가합니다.
3. 파일을 저장한 뒤 kmux를 다시 시작합니다.

```json
{
   "agents": {
      "local": {
         "claude": {
            "command": "ccs",
            "args": ["enterprise"]
         },
         "codex": {
            "command": "ccsxp",
            "args": []
         }
      }
   }
}
```

`args`는 `command` 뒤, kmux가 만드는 세션 재개 인자 앞에 추가됩니다. 예를
들어 위 설정에서 Claude 세션은 `ccs enterprise --resume <id>` 형태로
실행됩니다.

설정한 명령어는 해당 세션이 실행될 로컬 또는 SSH 호스트의 `PATH`에서 찾을
수 있어야 합니다. 명령어를 찾지 못하면 kmux는 공식 CLI로 자동 대체하지
않으며 해당 세션의 재개를 비활성화합니다.
