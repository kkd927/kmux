## SSH Workspaces

You can now connect an SSH host directly as a kmux workspace. In remote
projects, you can split terminals, run multiple agent sessions side by side,
and continue working after reopening the app just as you do locally.

### Getting started

1. Add a connection under **Settings → SSH Connections**, or import an
   existing OpenSSH alias with **Sync SSH config**.
2. Choose **Convert to SSH Workspace...** from the Command Palette or the
   workspace menu.
3. Select a host, then choose whether to convert the current workspace or
   create a new one.

---

## Markdown Preview

You no longer need to switch between the terminal and an external editor to
review documents written by an agent. Click a Markdown file path shown in the
terminal to open a preview inside kmux.

### Getting started

1. Find a path to an existing Markdown file in the terminal.
2. **Command-click** it on macOS or **Control-click** it on Linux.
3. Review the document in the preview on the right while continuing your
   terminal work.

## Agent Launcher Commands

You can configure the command and fixed arguments kmux uses when resuming an
agent conversation from session history. This lets environments that use an
internal wrapper or a separate profile command continue existing sessions
without switching back to the official CLI.

Settings can be applied separately to local and SSH environments for Claude,
Codex, and Antigravity.

### Configuration

1. Choose **Settings → Open settings.json**.
2. Add a `command` and `args` for each agent under `agents.local` or
   `agents.ssh`.
3. Save the file and restart kmux.

```json
{
  "settingsVersion": 5,
  "agents": {
    "local": {
      "claude": {
        "command": "ccs",
        "args": ["enterprise"]
      },
      "codex": {
        "command": "ccsxp",
        "args": []
      }
    },
    "ssh": {
      "claude": {
        "command": "claude",
        "args": []
      }
    }
  }
}
```

The values in `args` are inserted after `command` and before the session-resume
arguments generated by kmux. For example, the Claude session above runs as
`ccs enterprise --resume <id>`.

The configured command must be available on the `PATH` of the local or SSH
host where the session runs. If it cannot be found, kmux does not fall back to
the official CLI and disables resuming that session.
